# BongoCat 风格白熊桌宠设计

## 目标

把当前整张图片切换改为由真实键盘和鼠标输入驱动的分层白熊桌宠。最终效果对齐 BongoCat 的 `standard` 模型：鼠标手跟随光标并响应左右键，键盘手移动到当前按键位置并下压，所有动作平滑回位。视觉只使用用户提供的 `white-bear-typing.jpg`，不使用生成图片，也不引入 BongoCat 的猫模型。

## 已验证的参考实现

BongoCat 的设备层使用 `rdev::listen` 接收键盘按下/释放、鼠标按下/释放和全局坐标，再发送统一的 `device-changed` 事件。前端以阻尼插值平滑鼠标坐标，将屏幕坐标映射到模型参数；键盘输入映射到模型支持的按键图片并设置手部按下参数。主窗口把背景、Live2D 模型和当前按键透明图层分开合成。

本项目复用这条数据流和阻尼公式，但继续使用 Win32 与 WinForms，不引入 Tauri、Vue、Pixi.js、Live2D SDK 或 BongoCat 猫模型。BongoCat 源代码为 MIT License；移植的算法思路和实质代码片段在第三方声明中保留版权与许可文本。

## 方案比较

### 方案 A：制作真正的 Live2D 白熊模型

动作能力最强，但必须在 Cubism Editor 中重新绘制被手臂遮挡的区域、建立网格、参数和变形器。单张 JPG 无法自动得到可靠的 Live2D 模型，还会引入 SDK、运行时和分发许可复杂度。暂不采用。

### 方案 B：从原图构建 WinForms 2D 分层骨骼（采用）

从原图确定性提取背景、身体、鼠标手和键盘手，通过蒙版、仿射变换和分层合成实现跟随、按压和回弹。它能保留原画，同时复现 BongoCat `standard` 模型的核心交互，并保持当前单文件 WinForms 架构。

### 方案 C：把 BongoCat 作为独立进程或 WebView 嵌入

可直接得到现成猫模型效果，但会把本地小工具变成双运行时应用，无法自然使用白熊原图，体积、启动速度和维护成本都明显上升。暂不采用。

## 架构

### 1. 全局输入服务

用 `GlobalInputService` 统一替代只计数的 `KeyboardHookService`：

- `WH_KEYBOARD_LL` 读取瞬时虚拟键码与按下/释放状态。
- `WH_MOUSE_LL` 读取全局光标坐标、左右键按下/释放。
- 回调中不渲染、不分配大对象、不写文件；只写入固定大小的最新状态。
- UI 线程以约 60 Hz 获取快照，鼠标移动只保留最新位置，避免事件队列堆积。
- 键值只存在内存状态中，用于动作映射；不记录、不保存、不上传，退出或释放按键后立即移除。
- 安装失败不再静默：托盘显示“桌宠输入监听不可用”，桌宠仍可保持待机。

### 2. 白熊分层骨骼

`WhiteBearRigBuilder` 从嵌入的原始 JPG 构造以下运行时图层：

- `Base`：桌面、键盘、鼠标垫和补齐后的静态白熊身体。
- `MouseArm`：画面左侧手臂与鼠标区域，枢轴位于肩部，目标位置由鼠标坐标控制。
- `KeyboardArm`：画面右侧手臂，枢轴位于肩部，末端目标为键盘按键坐标。
- `Face` 保持在基础层，不单独变形，避免单图重建造成角色漂移。

图层通过固定的归一化蒙版从原图提取。移除手臂后露出的区域只用原图已有的白色、灰色和黑色线条规则补齐，不生成新的角色细节。输出仍在运行时产生，不覆盖用户原图。

### 3. 输入到动作的映射

- 鼠标位置按当前显示器工作区归一化到 `[-1, 1]`，使用 BongoCat 同类阻尼公式平滑。
- 鼠标手在鼠标垫有限范围内平移和轻微旋转；左键按下时下压，右键按下时增加另一方向的轻微倾斜。
- 键盘虚拟键映射到键盘的行、列，再通过四边形透视插值转换为原图键盘坐标。
- 键盘手从肩部朝目标键做平移、旋转和小幅缩放；按下时额外下压，释放时弹回待机位置。
- 多键同时按下时采用 BongoCat `single` 模式：键盘手跟随最近按下且尚未释放的键；该键释放后回到仍按住的上一个键，没有按键时回到待机。
- `Esc`、功能键、修饰键和无法精确定位的键映射到对应键盘区域或最近的通用位置，不显示键名。

### 4. 渲染循环

`DesktopPetRigController` 保存目标状态和当前状态。16 ms UI 定时器只在状态尚未收敛或有按键按下时重绘；静止后停止定时器，保持零持续重绘。`PetOverlayForm` 继续使用分层窗口一次呈现完整位图，不改变置顶、无焦点和鼠标穿透行为。

### 5. 设置与提示

现有“桌面宠物”开关继续控制整个功能。托盘增加只读状态：输入钩子正常时不打扰用户；失败时显示明确提示。README 的隐私说明改为“瞬时读取按键身份，仅用于本地动作映射”。

## 错误处理

- 键盘或鼠标钩子任一安装失败：释放已安装的钩子，保留静态桌宠，并提供 Win32 错误码。
- 分层资源构建失败：回退到用户原图透明化后的静态显示，不使用旧的整图晃动动画。
- 显示器切换、DPI 或工作区改变：重新计算鼠标归一化范围，不改变用户拖动后的桌宠位置。
- 高频输入：鼠标位置合并，键盘只维护当前按键集合，钩子回调不等待 UI。

## 测试

- 输入状态：按下/释放顺序、多键回退、未知键、鼠标按钮和坐标合并。
- 键盘映射：代表性的左上、中央、右下和修饰键落在键盘四边形内。
- 阻尼：位置单调趋近目标，不越界，60 Hz 与不同帧间隔结果接近。
- 分层：原图哈希保持不变，背景透明，静态身体不因手臂移动而漂移，两只手的像素包围盒分别变化。
- 生命周期：启用、禁用、钩子失败、窗体关闭和重新启用不会遗留钩子或定时器。
- 回归：完整 MSTest、Release build、win-x64 self-contained single-file publish；真实全局输入和透明窗口仍在 Windows 10/11 手工验证。

## 完成标准

在记事本等普通应用中移动鼠标时，白熊鼠标手在鼠标垫范围内平滑跟随；点击左右键有下压反馈。按键时，键盘手移动到对应键盘区域并下压；连续输入时动作跟得上且不闪烁，松开后自然回位。窗口保持透明置顶和鼠标穿透，应用不保存任何键值或输入历史。
