# WinForms 窗口频闪排查笔记

## 症状

- 拖动窗体边缘改变大小时，背景、卡片或控件短暂露白。
- 滚动内容时，动画区域闪一下，旧帧与新布局交替出现。
- 切换页面时，先看见半完成的布局，随后控件才补齐。
- 透明窗体偶尔留下旧轮廓、黑底或短暂消失。
- 单个控件平时正常，一旦 resize、layout、scroll 和 animation 同时发生，频闪明显加重。

## 第一性原理

频闪通常来自 resize、layout、scroll、animation 多个画面生产者重复无效化，以及透明窗体的 GDI 生命周期问题。resize 触发布局，layout 改变子控件边界，scroll 搬动可视区域，animation 又持续请求下一帧。它们各自都合理，但如果在同一小段时间内反复擦除背景、布局和绘制，用户就会看见中间状态。

透明窗体还有另一组风险。分层窗口的位图生成、GDI 对象选入与还原、设备上下文释放、旧位图替换和托管 `Bitmap` 释放必须形成完整生命周期。任一步顺序不对，都可能表现成黑块、残影、句柄增长或偶发空帧。这里要先分清普通子控件重绘与透明分层窗口呈现，二者不能靠同一个开关包治。

排查时先回答四个问题。

1. 谁在调用 `Invalidate`、`Refresh` 或触发布局。
2. 同一轮交互里有几个计时器或事件源在生产画面。
3. 用户是否看见了布局和绘制之间的中间状态。
4. 每一帧创建的 `Bitmap`、`Graphics`、GDI 句柄和设备上下文由谁释放。

## 适用解决方案

### 普通设置页

优先给真正频繁滚动或绘制的局部容器启用双缓冲。交互开始时暂停非必要动画，交互结束后恢复。页面切换时先暂停布局，完成可见性和层级调整，再恢复布局并统一请求一次重绘。

### 含多个子窗口的页面区域

当局部页面宿主需要让多个 WinForms 子窗口一起完成绘制，可以只在这个宿主上使用 `WS_EX_COMPOSITED`。这样 Windows 会在该局部区域按子窗口顺序完成离屏绘制，再一次呈现。它适合明确的小范围宿主，不适合无条件施加到整个窗体。

### 透明分层窗口

使用一张完整的 32 位预乘 alpha 位图生成当前帧，再通过一次分层窗口更新提交。新帧成功呈现后才能释放旧帧。临时 `Graphics`、`GraphicsPath`、`Matrix`、画刷、画笔、设备上下文和 GDI 位图都应在所属帧结束时成对释放。

## 本项目采用的方案

设置页的频闪处理由四部分组成。

1. `SettingsForm` 自身启用双缓冲，滚动区域使用 `BufferedScrollPanel` 做局部双缓冲。
2. `CompositedPageHost` 只给设置页与角色页的页面宿主增加 `WS_EX_COMPOSITED`，让这个局部区域完成子窗口合成后一次呈现。
3. 用户拖动缩放时，从 `ResizeBegin` 到 `ResizeEnd` 暂停预览动画。滚动发生后也暂停动画，连续 120 毫秒没有新的滚动事件才恢复。
4. 隐藏页停止预览。切页时先 `SuspendLayout`，完成显示、置顶和隐藏，再 `ResumeLayout`，最后统一无效化页面宿主。

这套方案确实是本项目设置页的频闪解决方案。它没有给整个设置窗体强制使用 `WS_EX_COMPOSITED`。桌面宠物与提醒动画属于透明分层窗口，依靠完整位图的一次呈现和严格的 GDI 生命周期管理处理画面更新。

## 实现要点

- 缓冲放在高频滚动或绘制的局部容器，范围越清楚越容易验证副作用。
- 动画暂停应覆盖 resize、scroll settling 和页面隐藏三种状态，恢复条件要集中计算。
- 滚动恢复使用短暂空闲窗口合并连续事件，避免每个滚轮刻度都停一次、起一次。
- 页面切换只改变一次可见性和层级，避免多个控件各自触发整页刷新。
- 动画计时器要防止重入。慢帧期间不应让新的计时事件持续堆积并挤占 UI 消息。
- 每帧位图的所有权要写清楚。呈现端借用到下一帧时，生产端应在替换成功后释放上一帧。
- 透明分层窗口使用预乘 alpha 像素格式，避免边缘发黑和重复混合。

## 禁忌

- 不要把 `WS_EX_COMPOSITED` 强制加到整个顶层窗体后就停止排查。它可能增加输入延迟、滚动拖影和大面积重绘成本。
- 不要在 `Paint`、`Resize`、`Layout`、`Scroll` 和动画计时器里互相调用 `Refresh`，这会把一次交互放大成同步重绘链。
- 不要让隐藏页的动画继续计时和无效化。
- 不要在一帧尚未呈现时释放位图，也不要在新帧成功后忘记释放旧位图。
- 不要只观察 CPU。GDI 句柄持续增长、窗口消息饥饿和布局次数异常同样会导致卡顿与频闪。
- 不要用单次肉眼观察替代压力验证，也不要把单机结果写成所有显卡、DPI 和 Windows 版本都已验证。

## 验证清单

- [ ] 在 100%、125% 和 150% DPI 下打开设置页。
- [ ] 连续拖动四条窗体边缘和四个角，观察背景、卡片与预览区。
- [ ] 快速上下滚动设置页，确认交互期间动画暂停，停止后恢复。
- [ ] 在设置页与角色页之间快速切换，确认隐藏页不再播放，页面没有半完成状态。
- [ ] 悬停不同角色卡片后立刻滚动或缩放，确认只有当前可见页面恢复动画。
- [ ] 反复开启和关闭桌面宠物，观察透明边缘、残影、黑底和旧帧。
- [ ] 连续移动鼠标、点击和键入，确认透明宠物动作连续且不阻塞其他窗口输入。
- [ ] 用任务管理器或诊断工具观察 GDI 对象数量，反复操作后不应持续单向增长。
- [ ] 分别在 Windows 10 与 Windows 11 上检查，记录显卡、DPI 和缩放条件。
- [ ] 将自动化测试与人工观察分开记录，不把未运行的新 EXE 行为写成已验证。
